# Calls Recognize

Расшифровка записей созвонов в текст на русском языке. Загружаете видео или
аудио (или указываете папку) — получаете распознанный текст и субтитры с
таймкодами (`.srt`). Есть встроенный **MCP-сервер**, чтобы ИИ-агент мог
управлять сервисом.

Построено на [faster-whisper](https://github.com/SYSTRAN/faster-whisper)
(CTranslate2), без torch. Работает на NVIDIA GPU, а без неё — на CPU.

## Возможности

- **Файл или папка.** Один файл = один результат: `output/<имя>/<имя>.txt`,
  `.srt` и `meta.json` (модель, язык, длительность, дата). Папка обходится
  рекурсивно; можно загрузить несколько файлов через браузер или положить их
  в `input/` и выбрать в проводнике. Повторная расшифровка файла с тем же
  именем не затирает прошлую: результат ляжет в `output/<имя> (2)/`.
- **Словарь терминов.** Названия продуктов, систем, имена (вкладка
  «Расшифровка» → «Словарь терминов» или `set_terms`). Подсказывается модели
  в каждом окне распознавания (параметр `hotwords`), хранится в
  `output/settings.json`.
- **Защита от галлюцинаций и потерь.** Ошибка одного окна не тянется в
  следующие (`condition_on_previous_text=False`), тишина не отдаётся модели на
  додумывание, типовые выдуманные фразы («Продолжение следует...», повторы
  реплики за доли секунды) вырезаются. Куски, где Whisper «проглотил» речь
  (длинный сегмент почти без слов), перераспознаются отдельно. Что убрано,
  что восстановлено и что восстановить не удалось — в `meta.json`.
- **Разделение по говорящим.** Галочка «Разделять по говорящим» (или
  `diarize=true`): реплики помечаются «Говорящий 1», «Говорящий 2»…
  Работает на sherpa-onnx (pyannote-сегментация + отпечатки голоса NeMo
  TitaNet-large, без torch); модели (~110 МБ) качаются при первом запуске. Число говорящих
  можно задать, иначе подбирается само.
- **Время по Москве.** `created` в `meta.json` — по `TZ` (по умолчанию
  Europe/Moscow), `recorded` — время начала записи из метаданных файла, если оно там есть.
- **Модели Whisper.** Таблица: скачана / размер / **есть обновление** на
  Hugging Face / доступна. Скачать, удалить, проверить обновления, выбрать
  какие модели показывать.
- **MCP / HTTP-API.** Фоновая расшифровка: `start_transcribe` → `job_status`
  / `cancel_job` / `list_jobs` (задачи идут по одной). С ожиданием результата:
  `transcribe`. Также `list_transcripts`, `read_transcript`, `get_terms`,
  `set_terms`, `list_models`, `download_model`, `delete_model`,
  `set_enabled_models`, `runtime`.
- Видео читается напрямую (встроенный ffmpeg). Русский по умолчанию, есть
  автоопределение языка, VAD-фильтр тишины, реальный прогресс, кнопки «Стоп».
- Экспорт: сплошной текст или «каждая реплика с новой строки».

## Запуск через Docker

```bash
docker compose up -d --build
```

Откройте <http://localhost:7861>.

- `input/` — сюда кладите записи для расшифровки папкой/файлом.
- `output/` — сюда сохраняются результаты.
- Модели кешируются в томе `whisper_cache` (качаются один раз).

## Подготовка к сборке образа

Образ ставит библиотеки CUDA и сборку sherpa-onnx с поддержкой GPU из локальной
папки `wheels/` (в git она не входит, около 1,5 ГБ). Перед первой сборкой
положите в неё шесть файлов для Python 3.11, Linux x86_64.

Пять библиотек NVIDIA — с PyPI:

```bash
pip download nvidia-cublas-cu12==12.4.5.8 nvidia-cudnn-cu12==9.1.0.70 \
  nvidia-nvjitlink-cu12==12.4.127 nvidia-curand-cu12==10.3.5.147 \
  nvidia-cuda-runtime-cu12==12.8.90 --no-deps --only-binary=:all: \
  --python-version 3.11 --implementation cp \
  --platform manylinux2014_x86_64 -d wheels
```

Сборка sherpa-onnx с CUDA — со страницы
<https://k2-fsa.github.io/sherpa/onnx/cuda.html>, файл
`sherpa_onnx-1.13.8+cuda12.cudnn9.onnxruntime1.28.2-cp311-cp311-linux_x86_64.whl`.

Без NVIDIA GPU эти шаги из `Dockerfile` можно убрать: Whisper сам перейдёт на
CPU, а для разметки говорящих задайте `DIARIZATION_PROVIDER=cpu`.

## Ускорение на GPU

Сервис сам использует NVIDIA GPU, если она проброшена в контейнер
(`WHISPER_DEVICE=auto`): `float16` на CUDA — в 10–30 раз быстрее CPU.
Нужны драйвер NVIDIA на хосте и Docker Desktop с WSL2 (блок `devices` в
`docker-compose.yml`). Без GPU — автоматический откат на CPU со всеми ядрами.
Текущая среда показана в шапке интерфейса, во вкладке «Модели» и через
MCP-инструмент `runtime`.

Файл `.srt` рядом с `.txt` — те же реплики, но с таймкодами (формат SubRip):
можно открыть как субтитры в плеере или найти момент в записи.

## Подключение ИИ-агента (MCP)

MCP-сервер доступен по адресу `http://localhost:7861/gradio_api/mcp/sse`.

**Клиент с поддержкой SSE:** укажите этот адрес как MCP-сервер.

**Клиент, запускающий MCP-серверы командой** (через `mcp-remote`):

```json
{
  "mcpServers": {
    "calls-recognize": {
      "command": "npx",
      "args": ["mcp-remote", "http://localhost:7861/gradio_api/mcp/sse"]
    }
  }
}
```

Пути для `transcribe` — внутри контейнера (`/app/input/meeting.mp4`) или
относительно папки `input/` (`meeting.mp4`, `2026-09/`). Схема HTTP-API:
`http://localhost:7861/gradio_api/openapi.json`.

## Запуск локально (Python)

```bash
pip install -r requirements.txt
python app.py
```

Нужен установленный `ffmpeg`. Откройте <http://localhost:7861>.

## Настройки (переменные окружения)

| Переменная | По умолчанию | Описание |
|---|---|---|
| `WHISPER_MODEL` | `large-v3-turbo` в Docker, `small` без переменной | модель по умолчанию |
| `WHISPER_COMPUTE_TYPE` | `int8` | `int8` (быстро) / `int8_float16` / `float32` |
| `WHISPER_LANGUAGE` | `ru` | `ru` или `auto` |
| `WHISPER_DOWNLOAD_ROOT` | — | куда качать модели |
| `INPUT_DIR` | `input` | папка с записями |
| `OUTPUT_DIR` | `output` | папка результатов |
| `HF_TOKEN` | — | токен Hugging Face (быстрее скачивание, без троттлинга) |
| `WHISPER_HALLUCINATION_SILENCE` | `2` | тишина длиннее порога (сек) не отдаётся модели; `0` — выкл. |
| `DIARIZATION_DIR` | `<WHISPER_DOWNLOAD_ROOT>/diarization` | модели разделения по говорящим |
| `DIARIZATION_PROVIDER` | `cuda` | где считать разметку говорящих: `cuda` или `cpu` |
| `DIARIZATION_NUM_THREADS` | `2` | вспомогательные потоки CPU для разметки |
| `DIARIZATION_THRESHOLD` | `0.5` | порог кластеризации голосов: больше — меньше говорящих |
| `DIARIZATION_MERGE_THRESHOLD` | `0.6` | второй проход: кластеры с похожим отпечатком голоса склеиваются в одного говорящего; ниже 0.6 слипаются разные люди; `0` — выкл. |
| `TZ` | `Europe/Moscow` (в Docker) | часовой пояс для `created` и `recorded` |

Набор доступных моделей и словарь терминов хранятся в `output/settings.json`.

## Как устроено разделение по говорящим

- Сегментация речи и отпечатки голоса считаются на NVIDIA GPU
  (`DIARIZATION_PROVIDER=cuda`), кластеризация и подготовка звука — на CPU;
  число вспомогательных потоков CPU задаёт `DIARIZATION_NUM_THREADS`.
- Разметка идёт в отдельном процессе, чтобы её библиотеки не конфликтовали с
  Whisper. Если GPU недоступна, скрытого отката на CPU нет: ошибка попадает в
  `diarization_error` в `meta.json`, текст расшифровки сохраняется. Для работы
  без GPU задайте `DIARIZATION_PROVIDER=cpu`.
- Первичная кластеризация сравнивает короткие отрезки и на длинной записи
  дробит один голос на десятки меток. Поэтому есть второй проход: кластеры
  склеиваются по усреднённому отпечатку голоса
  (`DIARIZATION_MERGE_THRESHOLD`), голос, которому на всю запись досталось
  меньше 5 секунд, отдаётся ближайшему по времени участнику, а обрывок в
  одно-два слова посреди чужой фразы возвращается этой фразе.
- Если число говорящих задано вручную, второй проход не выполняется.
- Ограничение: участник, сказавший за всю запись меньше 5 секунд, отдельной
  метки не получит. Имён сервис не знает.
